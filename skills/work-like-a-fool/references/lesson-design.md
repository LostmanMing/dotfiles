# 课程页写法与图表规范

## 1. 课程规划原则

**按测评结果裁剪，不要给通用大纲。** 具体做法：

| 维度状态 | 处理方式 |
|---|---|
| 扎实（≥80%） | **明确写出「这节跳过」**，只保留 1–2 个与任务直接相关的进阶点 |
| 半懂（55–80%） | 只讲缺的那部分，用「你已经会 X，缺的是 Y」开头 |
| 薄弱（30–55%） | 完整讲，但可假设术语能听懂 |
| 空白（<30%） | 从零讲，先建最小心智模型再展开 |

在首页放一张 **诊断表**（维度 / 测评状态 / 课程策略），让学习者一眼看到
「我的时间会花在哪、哪些不用看」。这一步能显著提升完成率。

再放一个 `<div class="key">` 说清**「你缺的不是 X，而是 Y」**——
把学习者自己的焦虑（「我不懂深度学习」）转换成实际缺口（「你缺的是这个 C++ 项目的架构」）。

## 2. 单页结构

每节按这五段写，顺序不要变：

1. **你已经会的部分** — 用 `<div class="note">`。明确说哪些可跳过，省时间也建立信任。
2. **新知识** — 概念 → 图 → 代码 → 表格对比。**先图后文**，不要先堆一大段文字。
3. **本机实测** — 用 `<div class="real">`。真实跑出来的输出/数字（见 grounding.md）。
4. **动手** — 可直接复制粘贴执行的命令，含具体路径，不用占位符。
5. **自测** — 3–5 个 `<details><summary>Q：</summary>答案</details>`。
   问「后果」和「为什么」，不问定义。

## 3. 可用样式类

```html
<h2 class="sec">章节标题</h2>          <h3 class="sub">小节标题</h3>
<div class="note">提示（蓝）</div>      <div class="warn">坑（橙）</div>
<div class="key">要点（绿）</div>       <div class="real">本机实测（绿，带徽章）</div>
<table>...</table>                     <pre><code>...</code></pre>
<figure><img src="assets/img/x.svg"><figcaption><b>图 N-1</b>　说明</figcaption></figure>
<details><summary>问题</summary>答案</details>
<div class="mods"><a class="mod" href="m01.html"><span class="n">M1</span>
  <div class="t">标题</div><div class="d">这节解决什么</div></a></div>
```

代码块内可用高亮 span：`cm`(注释) `kw`(关键字) `st`(字符串) `fn`(函数名) `hi`(黄色强调)。
**`hi` 用来标出「这一行是重点」**，比在正文里说「注意第 4 行」有效得多。

## 4. 图表规范（SVG，手写，存 assets/img/）

**必须画图的四类内容**（用户明确要求「涉及算法的要用图展示」）：

1. **分层/架构** — 谁在谁上面，各层职责
2. **调用链/时序** — 一个操作从入口到底层的完整路径，标出可介入的位置
3. **数据结构** — 内存布局、指针关系、共享关系
4. **算法机制** — 分页、调度、批处理、状态机、前后关联

### 硬性要求

- **手写 SVG 文件**，不要 base64、不要外部依赖、不要 mermaid（无法离线渲染）。
- 固定调色板（与 style.css 一致）：
  ```
  背景 #0d1117   卡片 #161c24   边框 #2a333f
  正文 #d6dee8   次要 #8b98a8
  蓝 #4cc2ff（主/概念）  绿 #7ee787（正确/推荐）
  橙 #ffb86b（注意/次要路径）  红 #ff7b72（错误/问题）  紫 #d2a8ff（框架层）
  ```
- 字体统一 `ui-monospace,Menlo,Consolas,monospace`；正文 11–12px，标题 12.5px，标注 10.5px。
- 用 `viewBox` + 显式 `width/height`，页面里靠 `figure img{width:100%}` 自适应。
- **每张图必须自带结论**：在图内用一行文字写出「所以…」，不要指望读者自己总结。
- 对比类的图用**左右分栏**（左错右对、左朴素右优化），比上下排列更容易看出差异。
- 画完用 `python3 -c "import xml.dom.minidom as m;m.parse('x.svg')"` 校验（validate.py 会做）。

### 常用画法

```
分层：       纵向堆叠 rect，右侧留一列标注每层的作用/可介入点
调用链：     纵向 rect + 箭头，右半页留「这一层能拿到什么」的注释列
时间线/甘特： 横向 rect，左侧一列泳道名，底部一条时间轴
数据结构：   rect 内用等宽文本列字段，intrusive_ptr 关系用虚线箭头
对比：       两个大 rect 左右并列，各自带 ✓/✗ 结论
```

## 5. 语言

- 中文正文 + 英文技术术语原文（首次出现给中文解释，之后直接用英文）。
- 每节开头一句话写清「读完你能做什么」，用能力而非知识点描述。
- 结论先行：先给答案，再解释为什么。
- **不要写「这很简单」「显然」**这类词——学习者卡住时会更沮丧。
